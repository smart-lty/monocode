# MonoCode 个人分支重建计划

更新：2026-10-11。这是讨论用的工作文档，定下来的内容直接改在这里。

## 目标

上游更新很快（两天 39 个提交），大部分定制都要自己长期维护。这次重建只保留真正需要的功能，尽量少改上游常改的文件，降低以后每次同步的成本。

## 做法

- 从最新的上游 main 新建分支 `personal-v2`，在单独的 worktree 里做。旧的 `personal` 分支和现在的工作区保持不动。
- 动手前，把当前所有未提交的改动存成一个快照提交，推到 `fork`。之后从快照里摘代码，快照也是兜底的备份。
- 先放上游 PR，再放自己的改动。上游 PR 一律原样放入，上游合并后直接删掉对应的提交。
- 每个功能一个提交，改动尽量小。新逻辑尽量写在新文件里，`App.tsx` 只留接入代码。
- 日常维护：每隔一两天 rebase 到上游一次，打开 `git rerere`，rebase 后用 `git range-diff` 核对。
- 锁屏：只会挡住需要操作窗口的验收，不影响命令行测试和构建。窗口验收集中在最后，等你在场时做。电脑真正休眠（比如用电池时合盖）才会让所有工作停下，长时间运行时用 `caffeinate -i` 或 magpie 的 Keep awake 防止休眠。

## 会话引用（待讨论）

### 要解决的问题

让一个会话里的 agent 能看到另一个会话里讨论过的内容。目前只能靠 `/operator` 让 agent 自己去读，或者手动复制粘贴。

### 15：完整读取会话

现在的 `sessions.read` 每次最多读 3 轮，每条消息最多 6000 字，读不到工具调用和思考过程。快照里已经有改进版：

- `view: "messages"` 只读消息；`view: "blocks"` 还包括工具调用和计划。
- 长消息可以从上次读到的位置接着往下读，不会丢字。
- 读的过程中会话有更新时会提示，避免把新旧内容拼在一起。
- `sessions.export` 把完整记录导出成文件，只返回路径和一份简短清单。

默认只读消息；需要工具调用时再用 `blocks`，需要全部内容时用 `export`。这个提交不改 UI，冲突风险小，也适合提给上游。

### 16：用户看到的样子

- 在输入框里输入 `#`，弹出当前项目最近的会话；输入 `##`，弹出所有项目的会话。可以继续输入文字来搜索。
- 列表每一项显示项目图标、模型、标题、最近活动时间和对话轮数。
- 选中后，输入框里多出一张引用卡片，可以删除。同一个会话不会重复添加。
- 发送后，消息里保留这张卡片，以后再看这条消息时，能知道当时引用了哪个会话。
- 以后可以加：从侧边栏把会话拖进输入框。

### 16：agent 收到什么

- 发送时，在消息后面附上一份引用目录：每个被引用会话的标题、项目、更新时间，以及读取它的命令。
- 第一次引用某个会话时，附上它的首次需求和最近几轮的摘录，并控制总长度。以后的轮次只保留目录。
- agent 需要更多内容时，自己用 15 的读取命令去读。
- 权限：只能读取被引用的会话，不能给它发消息，也不能修改它。不需要开启 `/operator`。
